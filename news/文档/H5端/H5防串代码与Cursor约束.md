# H5 防串代码与 Cursor 开发约束

> 配合 [H5接入方案.md](./H5接入方案.md)（范围已确认）。  
> 目的：独立 H5 工程与 PC `client` **长期并行**时，避免「改着改着把两端揉在一起」。

---

## 1. 什么叫「串代码」

| 现象 | 风险 |
|------|------|
| 在 `NewsInfo.jsx` 上加一堆 `isMobile` 分支当 H5 | PC 回归爆炸；违背路线 C |
| H5 直接 `import` PC 页面/Dashboard 壳 | 打包进桌面依赖，体积与交互双崩 |
| 为省事把 PC 表 + 写按钮拷进 H5 再隐藏 | 隐藏失效即越权写；逻辑双份难维护 |
| 改分享页做「手机版产品」 | 与已确认「分享不进 H5」冲突；移动端分享按钮本就不展示 |
| 一次 PR 混改估值工作台 + H5 舆情 | Review 无法按边界验收 |

---

## 2. 工程隔离（硬边界）

```
news/
  client/          ← PC 管理台（Arco、宽表、配置、作业台）
  client-h5/       ← 仅 H5 只读壳（移动组件库；一期才创建）
  server/          ← 共用后端；H5 只加只读路由或白名单 GET
  文档/H5端/       ← 方案与约束
```

- **构建分离**：两套 `package.json` / 两套 `dist`；Nginx `/`→PC，`/h5/`→H5。  
- **允许的 PC 改动**：同址跳转探针（登录/根路由探测 UA → `/h5/`），以及日后可选的「电脑版」链接。  
- **禁止**：把 PC 业务页改成响应式来替代 `client-h5`。

## 3. 基于当前 Cursor 的防串做法

本仓已用 Cursor Rules / Skills。落地如下（**研发开工前就位**）：

### 3.1 Project Rule（已加）

路径：`.cursor/rules/h5-isolation.mdc`

- `globs` 覆盖 `news/client-h5/**`、登录/App 跳转相关、H5 文档、未来 `h5` 路由。  
- Agent 打开这些文件时自动带上「只读 / 不碰分享 / 不改 NewsInfo 当手机版」等约束。

### 3.2 会话习惯（给你和 Agent）

| 做法 | 说明 |
|------|------|
| **开新 Chat 做 H5** | 标题或首句写明：`H5 only · client-h5 · 只读舆情`；避免与「改专队/估值」同一长会话缠在一起 |
| **@ 方案文档** | 开工时 `@news/文档/H5端/H5接入方案.md` 与本文 |
| **禁止口头「顺便」** | 若 Agent 提议「顺便把 ShareNewsPage 适配一下」→ 按已确认范围拒绝 |
| **改动清单自检** | 每个 PR/`git status`：H5 文件 vs PC 探针 vs server 只读，三类分开看 |

### 3.3 可选加强（二期工程化）

- `client-h5` 内 ESLint `no-restricted-imports`：禁止 `from '../client/'` 或 `@pc/*`。  
- CI：`client-h5` 的依赖图中不得出现 `client/src/pages`。  
- PR 模板勾选：是否仅 H5 / 是否含 PC 探针 / 是否含写接口（应为否）。

### 3.4 可共享 vs 不可共享

| 可共享（谨慎） | 不可共享 |
|----------------|----------|
| API 路径字符串、时间范围枚举、纯格式化函数 | React 页面组件、Arco Table 列定义、Dashboard 布局 |
| 后端只读 DTO | 写操作 action、导出、AI 重跑 |
| 鉴权 Token 读写约定（同源 localStorage） | 分享 Token 体系与 H5 会话混用 |

一期若尚无 `shared` 包：**允许** H5 侧薄封装 axios + 常量复制；**不要**为了 DRY 去抽半成品共享组件。

---

## 4. 分享页专项

- PC 上移动端 **已不展示**分享相关按钮 → **无需求**做分享 H5 化。  
- 同址跳转规则：**排除** `/share/*`、`/performance/share/*`、`/publish/*` 等。  
- Agent / 人工：**不得**以「手机打开分享链体验不好」为由于一期改分享页进 H5 壳。

---

## 5. 自检清单（每次 H5 相关提交前）

- [ ] 新 UI 是否都在 `client-h5`（除跳转探针）？  
- [ ] 是否引入任何写操作按钮或写 API？  
- [ ] 舆情是否走「我的企业」/`user-news` 口径？  
- [ ] 是否改动了 Share* 页面？（预期：否）  
- [ ] 是否把 PC `NewsInfo` 改成双端？；（预期：否）
