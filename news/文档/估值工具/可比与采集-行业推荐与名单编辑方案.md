# 可比与采集：行业/赛道推荐上市备选 + 名单编辑删除

> 入口：项目估值工作台 → **可比与采集** → 「可比上市公司」。  
> 实现前仅方案，不改业务代码。确认后再按文末分期落地。  
> 「已拍板」含方案 grilling + 开发经理评审澄清，实现以本文为准。  
> **方案 grilling 已收束**，可按 §9 分期（P0→P1）排期实现。

## 1. 要解决什么

当前名单只有三条进数路径：从最新成功竞品分析加载、手工股票代码、Excel 导入。表格没有「操作」列，不能改代码/名称，也不能删行。

缺口：

1. 竞品分析召回的是融资事件/未上市主体为主；估值 POOL 需要的是 **A 股（含北交所；新三板可选手动纳入推荐）上市备选**。标的已有行业标签、四大类、申万赛道时，应能直接从上市主档里捞最接近的公司。
2. 分析师需要对名单做 **编辑、删除**，且后续「从竞品分析加载」不能把手工改过的行整表冲掉。
3. **主路径体验**：不依赖手工录入、也不依赖「从竞品分析加载」时，仍能一键按行业经验拿到上市备选；预览里能看 **推荐理由** 与 **企业介绍**，便于判断是否合适再勾选进名单。

港股美股仍不入池（与现口径一致）。不做「完全替换名单」危险操作。

## 2. 产品位置与交互

### 2.1 主路径（零名单 / 不走竞品时）

可比页工具栏按钮顺序调整为：

1. **按行业/赛道推荐**（主路径，视觉可 primary）
2. 从最新成功竞品分析加载
3. 手工代码 / 添加 / Excel 导入

空名单时顶部引导（非阻断）：「可点「按行业/赛道推荐」，按标的行业/赛道从上市主档挑选可比公司；无需先跑竞品分析。」

**草稿约束（已拍板）**：仅 **当前草稿** 视图可发起推荐 run、打开结果确认 apply；与采集/计算一致。正式版本视图：推荐发起/apply 禁用或隐藏，Toast「请先切换到当前草稿，或发起新版本后再推荐」。历史 success run 若需只读查看可后置；P1 正式版不提供 apply。

| 按钮 | 行为 |
|------|------|
| **按行业/赛道推荐** | 打开宽预览弹窗，勾选后合并进当前名单 |
| （表格）**操作：编辑 / 删除** | 行内改代码或可比属性；软删 |

### 2.2 推荐：非阻断执行 + 版本 + 完整结果再看

**目标体验**：点「按行业/赛道推荐」后用户不被卡住；**规则召回 + AI 业务理由全部跑完**后，才打开「推荐企业」宽表弹窗（理由、简介、业务维齐全，便于判断）。确认进名单仍按 §6 合并，并 **自动 `selected=1`**。

#### 2.2.1 点击与防抖

- 5 秒内重复点击同一按钮，或 **上一次 run 仍在 `running`**：不发起新任务，Toast「推荐进行中 / 请稍后再试」；**默认只跑一次**。
- **P1 不提供「取消本次推荐」**：关进度弹窗不取消任务；点错参数需等本版结束（success/failed）后再开新版。
- **超时**：run 超过时限仍未结束 → 标 `failed`（或 `timeout`），按钮回默认并可提示失败原因；时限由环境变量控制，**默认 5 分钟**（如 `VALUATION_RECOMMEND_RUN_TIMEOUT_MS=300000`）。
- 若存在已完成且未查看的最新成功版本，再次点击可优先提示「查看上次结果」或直接打开该版（实现二选一，优先：绿按钮旁「查看本次推荐」）。

#### 2.2.2 进度弹窗（非阻断）

点推荐后立即弹出进度提示（可拖、可关）：

- 文案示例：「程序正在执行中，正在按行业/赛道分析可比上市企业…」
- 操作：**「确认」与「X」均为关闭进度弹窗**（不取消后台任务；后台继续跑）。
- 关闭后用户可继续改方法配置、看名单等；任务在服务端/案件维度继续。

#### 2.2.3 按钮状态（主工具栏「按行业/赛道推荐」）

| 状态 | 按钮外观 | 行为 |
|------|----------|------|
| 空闲 / 无可查看版本 | 默认样式 | 点击 → 防抖后创建新 run |
| 执行中 | **红色**（或 danger） | 点击不新建；可再次打开进度提示 |
| 最近一次成功完成 | **绿色**（或 success） | 点击可「再跑一版」（仍受防抖）；另见查看按钮 |

执行完成后：

- 推荐按钮变为 **绿色**。
- 旁侧（或同区）出现 **「查看本次推荐的企业信息」**（打开该次成功版本的结果宽表）。
- 可选轻量通知：「推荐已完成，可查看结果」。

#### 2.2.4 结果宽表弹窗（仅成功版本、数据齐全后）

- **宽度**：约 `min(96vw, 1280px)`；表可横滚。
- **打开时机**：该版本 `status=success` 且候选+规则理由+（尽量）AI 业务维已齐；**禁止**在半成品状态打开选企业表。
- 顶部：本版 `version_no`、用到的标的画像、是否含新三板/是否放宽；可切换「历史版本」（最近成功 N 版，见 §2.2.5）。
- 勾选「含新三板」、放宽：属于 **发起 run 时的参数**；查看历史版时只读当时参数（改参数需再点推荐开新版）。
- **表列**：勾选、代码、名称、市场、四大类、申万三级、匹配分、**匹配说明**、**企业简介**、状态（已在名单 / 曾删除 / 可新增）。
- 匹配说明 / 企业简介：限高约 2～3 行，悬停全文；分维含行业/赛道标签/透镜/业务·AI。
- 企业简介：`product_intro` → `company_intro` → 行业路径 +「暂无简介」。
- 默认勾选：匹配分 ≥ 60 且尚未在名单中的前 15 家；已在名单禁用。
- **确认加入名单**：按代码合并；成功写入/复活行 `selected=1`（自动勾选采集）；`in_pool` 按分 ≥60。提示：「已加入名单并勾选采集」。
- AI 整版失败：版本仍可 `success`（规则结果有效），业务维统一「业务理由暂不可用」；不阻断打开与确认。

#### 2.2.5 推荐版本（落库，已拍板）

表建议：`valuation_case_recommend_run`（案件维度）：

- `case_id`、`version_no`（案件内递增）、`status`（`queued`/`running`/`success`/`failed`）
- 参数：`relax`、`include_neeq`、`limit`、画像快照 JSON
- 结果：候选列表 JSON（含分、规则分维、简介、`business_reason` 等）或子表；`error_message`；时间戳与创建人
- **同一案件仅保留最近成功 N=5 版**（更早成功版可删或归档）；`failed` 可只留最近 1～2 条便于排错
- 「查看本次推荐」默认打开 **最新 success**；历史列表可切到其它 success 版再确认勾选（确认范围 = 当前打开版本中的勾选）

冷启动 Alert、空态文案同前：不要求先跑竞品；无候选时版本 `success` 且 list 空，查看时展示空态引导。

编辑与主表：

- 可改：股票代码、可比程度、是否入池、是否勾选。
- **可比程度、入池、勾选三项互不联动**（含主表 `Select` 与编辑弹窗）。P0 **改掉**现网「改强/中自动开池、改弱自动关池」行为；可比程度旁可加小字：「改可比程度不会自动改 POOL」。
- 代码失焦后走现有 `ipo_new_share` 解析，回填名称、市场、信用代码；解析失败或港美股则禁止保存。
- 名称、市场只读（以主档为准）。
- 改代码：新代码已在本案件**有效**名单中则拒绝。新代码仅存在于本案件**软删**行则拒绝，提示「该代码曾删除，请用手工添加或推荐勾选加回」。
- 改码成功后 **清空** 该行 `pe_median_override` / `ps_median_override`，保存前提示「将清除底稿覆盖」。旧行财报按代码存在公共表，不随行迁移。

删除：

- 二次确认：「删除后不再进入采集与 POOL。可用手工代码或推荐再次加回。」
- 软删 `F_DeleteMark = 1`。勾选关闭、入池关闭不替代删除。
- 前端删除只走 `DELETE`，不得再靠整表 PUT 表达「名单里没有了」。

表格现有列保留，末尾加 **操作**；「说明」继续表示不可用原因（无代码、港美股等）。**名单主表 P1 增加「匹配说明」列**（推荐确认写入的 `match_reason` 摘要；竞品/手工无则「—」），限高 + 悬停全文，避免关预览后无法回看理由。完整分维仍以预览展开为准。

## 3. 标的画像从哪来

按估值案件类型取主体，字段做并集，**后者只填前者空缺**（申万三级除外，见下）：

| 优先级 | 来源 | 字段 |
|--------|------|------|
| 1 | 投后 `invested_enterprises` / 投前 `sourcing_pre_investment_project` | `industry_category_4`、`sw_industry_l1/l2`、`ai_industry_tags_json` / `display`、`sub_track`（有则取） |
| 2 | 最近一次成功竞品 run 的 `S0_profile` | 四大类、申万一/二级、标签快照、`sub_track` |
| 3 | 竞争透镜 `competition_lens_json` | `must_align`、`custom_keywords`（短语加分，不单独当硬过滤） |
| 4 | 融资主档（信用代码对齐） | `industry_category_4`、`industry_std_lv1/lv2` |

**申万三级单独通道**：读本案件草稿 payload 的 `sw_industry_l3`。**只要非空就用**，与倍数来源是否为「申万三级中位数」、是否已点「确认」无关。空则**不猜三级**，漏斗不走「同三级」层，打分不加 +30；一、二级仍按上表并集回退。弹窗画像可注明来源：「来自方法配置（未用于行业法也可）」。

**`sub_track`：**

- 标的侧：竞品 `S0_profile` / 主体 meta。
- 上市侧：**没有** `ipo_new_share.sub_track`；用候选申万一/二级查 `sw_industry_category_map.sub_track`（与 Stage 1c 同一套）。
- 任一侧空则该项 0，不扣分。

不按具体公司名写死规则。

**排除自身**（有稳定键才排除，不做同名模糊）：

- 同一 `unified_credit_code`；或
- 同一 `stock_code`；或
- 投后/主档能解析到的上市代码（轻量并入排除集）。

都空则不排除，偶发自荐由人工去掉。

## 4. 上市宇宙与召回

宇宙：`ipo_new_share`，交易所 ∈ 上交所 / 深交所 / 北交所；**默认排除新三板**。query `include_neeq=1`（弹窗勾选「含新三板」）后再纳入。排除港美。

**上市状态（退市）：**

- 名称含「退市」→ 排除。
- 若主档后续有正式退市/终止上市字段 → 字段优先并用。
- **不**以是否出现在 `valuation_sw_constituent` 作为退市判断（避免误伤北交所/漏同步）。
- ST / *ST **仍可出**，靠人工去掉。

行业：表内 `sw_industry_l1/l2`、`industry_category_4`、`industry_tags_*`；缺三级时左连 `valuation_sw_constituent`（东财 EM2016）。  
四大类映射继续用 `sw_industry_category_map`，与竞品 Stage 1c 同一套。

召回各层（由窄到宽；**启用中的层都跑，不因凑满而关门**）：

1. 同 `industry_category_4` **且** 申万三级相同（画像有三级时）
2. 同四大类 **且** 申万二级相同
3. 同四大类
4. **仅当画像无四大类时**：「仅申万一级相同」。有四大类则**不跑**第 4 层。

`relax=1`：有四大类从第 3 层起；无四大类从第 4 层起。

**层内截断 `per_layer_cap`（默认 100，可配）：**

- 命中数 ≤ cap → **全取**，禁止无序 `LIMIT`。
- 命中数 > cap → 用可 SQL 化的**粗分**排序后再 LIMIT：四大类命中、申万级差、标签粗重叠（如 `industry_tags_display` 是否包含任一标的标签）等；出层后算第 5 节满分。
- `per_layer_cap` ≠ 接口 `limit`（最终 Top，默认 30，最大 50）。

各层合并去重后按满分排序取 Top。

**同一主体多代码**：候选有 `unified_credit_code` 时，同一信用代码只留匹配分最高的一只；同分优先 A 股（非 B 股），再按代码。无信用代码则不去重。手工/Excel 不加这层限制。

## 5. 匹配分（写入「综合分」）

各项相加后 **`min(总分, 100)` 封顶**。与现网 `comparabilityFromScore` 对齐：≥80 强、≥60 中、否则弱。

| 项 | 分 | 说明 |
|----|----|------|
| 四大类相同 | +25 | 标的无四大类则 0，不扣 |
| 赛道/sub_track 相同 | +15 | 上市侧来自 `sw_industry_category_map`；双端有值且相同才加 |
| 申万三级相同 | +30 | 画像无三级则本项 0；否则二级 +18，否则一级 +8 |
| 标签重叠 | 0–20 | 标的 AI 标签 vs 上市 `industry_tags_*`，Jaccard×20 |
| 透镜短语命中 | 0–15 | `must_align` / `custom_keywords` 出现在上市标签或产品/公司简介 |

推荐写入 `source = industry_recommend`，`relevance_score` = 封顶后的匹配分（**仅规则分**）。

**推荐首次写入 / 推荐勾选复活（产品硬规则）**：

- `selected=1`：**自动勾选采集**，确认进名单后主表无需用户再点勾选。
- `in_pool`：仅当匹配分 ≥ 60 时为 1（弱匹配也勾选采集，但不默认进 POOL）。
- 之后主表/弹窗改可比程度 **不**自动改入池或勾选；用户仍可手动关掉某行勾选。

这不是竞品分析综合分，**不跑、不展示**竞品「证据可信四维」（来源/新鲜度/一致性/判断强度）。同一行若已在有效名单（无论来源）：推荐确认 **跳过**，不覆盖综合分、来源、勾选、入池、底稿。

### 5.1 推荐理由（规则必出 + AI 自动补业务维）

目标：分析师在预览表里能看清 **行业一致 / 赛道标签 / 透镜命中 / 业务为何可比**，类似竞品「为何荐」的可读性，但口径是 **估值可比**，不是竞品证据可信。

**展示（预览表列 + 限高悬停）**

- 主列 **匹配说明**：摘要（规则拼装，例如 `行业一致·四大类生物医药；申万三级化学制药；标签重叠 2/5`）。单元格限高 2～3 行；悬停看全文 + **分维**（见下表）。
- 主列 **企业简介**：见 §2.2；与匹配说明同样限高 + 悬停全文。
- 分维内容（悬停/轻量展开均可，不另占多列）：

| 维 | 来源 | P1 | 说明 |
|----|------|----|------|
| 行业一致 | 规则 | 必有 | 四大类、申万一/二/三级命中情况 |
| 赛道/标签 | 规则 | 必有 | `sub_track`、标签 Jaccard 重叠明细 |
| 透镜命中 | 规则 | 有则显示 | `must_align` / `custom_keywords` 命中处 |
| 业务一致 | AI | P1.5 自动补 | 1～2 句人话：产品/客户/商业模式为何可作可比；**不改匹配分** |

**交互时序（已拍板，撤回「先出表再 AI」）**

1. 用户点「按行业/赛道推荐」→ 防抖通过 → 创建 `recommend_run`（`version_no++`，`running`）→ **进度弹窗**（可关，不取消任务）；按钮变 **红**。
2. 服务端同一次 run 内顺序（或可并行但 **全部结束后才标 success**）：规则召回 + 打分 + 规则分维 + 简介切片 → AI 业务理由批量 enrich（§5.2）→ 结果写入该版本。
3. run `success` → 按钮变 **绿**，出现「查看本次推荐的企业信息」；此时才允许打开结果宽表（数据齐全）。
4. 用户在宽表勾选并确认 → 合并进名单，`selected=1`，`match_reason` 用该版摘要（含已有 AI 句）；**不**把整版自动灌进名单。
5. AI 失败：版本仍可 success（仅缺业务维）；run 整体失败或 **超时** → 按钮回默认/提示失败，无绿色查看（或提供「查看失败原因」）。P1 无手动取消。

**与旧方案差异**：不再「弹窗内自动续跑 AI、半表可先勾」；避免用户对着半成品判断。

**AI 边界**

- **不**改落库匹配分、默勾、入池。
- **不**替代规则召回（宇宙过滤与漏斗仍是规则）。
- 调用走现网 `llmInvoke` 网关；案件权限与推荐接口相同。
- 与竞品 Stage AI 对标分无关：本处只产出「业务可比说明」，不当作另一套综合分。

### 5.2 AI 配置、提示词与取数（遵循现网「模型提示词」逻辑）

与 **融资 AI enrich / 竞品提示词** 同构：库表配置优先，代码内 builtin 仅作种子与 DB 空时降级，**禁止**业务代码写死 API Key 或生产提示词正文。

**挂载键（已拍板）**

| 项 | 值 |
|----|-----|
| `ai_prompt_config.interface_type` | `项目估值` |
| `ai_prompt_config.prompt_type` | `valuation_comparable_business_reason` |
| `ai_prompt_config.prompt_name`（种子） | `项目估值-可比推荐业务理由` |
| `ai_model_config.application_type` | `project_valuation`（与 `valuation/constants.js` 一致） |
| `ai_model_config.usage_type` | `project_valuation` |

运营在后台「模型提示词」改文案、启停、绑定模型；改完后运行时按现网缓存策略刷新（可对标竞品 `loadCompetitorPromptBundle` 短缓存）。

**模型解析顺序（对标 `financingAiEnrich` resolveLlmConfig）**

1. 读活跃提示词行：`interface_type=项目估值` AND `prompt_type=valuation_comparable_business_reason` AND `is_active=1` AND `F_DeleteMark=0`（按 `F_LastModifyTime DESC` 取 1）。
2. 若该行 `ai_model_config_id` 指向可用模型（`is_active=1`、未删、`api_key` 非空）→ **用绑定模型**。
3. 否则兜底：`application_type=project_valuation` AND `usage_type=project_valuation` 的活跃配置（同竞品 `getActive*ModelConfig` 写法）。
4. 仍无可用模型 → enrich 整体失败降级（业务维空），**不影响**规则预览表。

**提示词正文格式**

- 存 `ai_prompt_config.prompt_content`，结构同竞品：`---SYSTEM---` / `---USER---` 两段。
- USER 模板占位符（Mustache 风格，与竞品 `{{VAR}}` 一致）：
  - `{{TARGET_JSON}}`
  - `{{CANDIDATE_JSON}}`
  - `{{RULE_REASON_JSON}}`
- `initPrompts`（或估值侧 seed 函数）写入 builtin；**仅当库中无该 `prompt_type` 或内容与种子策略允许更新时**写入，不覆盖运营已改且需保留的正文（遵循现网 upsert 策略：已有行按 initPrompts 既有规则更新/跳过）。

**种子提示词大纲（实现时落入 builtin，可后台改）**

- SYSTEM：你是估值可比分析助手。仅依据输入 JSON 中的标的与上市候选原始信息，用 1～2 句中文说明 **业务上为何可作可比公司**（产品/客户/商业模式）。禁止编造未披露营收、客户、管线。不得否定或改写 `RULE_REASON_JSON` 中的规则命中事实；可补充业务解读。双方业务信息严重不足时输出「信息不足，无法判断业务可比性」。
- 输出纯 JSON：`{"business_reason":"…","confidence":"high|medium|low"}`（`confidence` 仅展示，不参与打分）。
- USER：标的 `{{TARGET_JSON}}`；候选 `{{CANDIDATE_JSON}}`；规则分维 `{{RULE_REASON_JSON}}`。

**取数逻辑（与规则推荐同一路径，禁止另起取数）**

| 块 | 来源 | 字段（有则传，无则省略/null） |
|----|------|------------------------------|
| `TARGET_JSON` | §3 画像并集 + 草稿三级通道 | `display_name`、`industry_category_4`、`sw_industry_l1/l2/l3`、`sub_track`、标签、透镜 `must_align`/`custom_keywords`、产品/企查查简介（主体或 S0 已有则带） |
| `CANDIDATE_JSON` | 本次预览已命中的 `ipo_new_share` 行（+ map 推导） | `stock_code`、`stock_name`、`listing_market`/`exchange`、`industry_category_4`、申万一/二/三级、`sub_track`（map）、`industry_tags_*`、`product_intro`/`company_intro` |
| `RULE_REASON_JSON` | 本行规则打分结果 | 分维摘要、各项是否命中、规则匹配分（只读参考） |

约束：

- **不**为 AI 再查全宇宙、**不**强制联网搜索（除非所绑 `project_valuation` 模型本身在网关层开启且配置要求；默认 `enableSearch=false`，与竞品 pair_similarity 一致）。
- **不**把竞品 `competitor_pair_similarity` 提示词或 `competitor_match` 模型挪来冒充；可复用 `llmInvoke` / 截断工具函数，提示词与模型键必须是项目估值套件。
- 批量：仅对当前预览列表（≤ `limit`）并发调用，限流对标竞品/融资 enrich 的网关并发配置。

**实现落点建议**

- `news/server/utils/valuation/listedIndustryRecommendPrompt.js`：PROMPT 常量、builtin、`loadValuationRecommendPromptBundle`、`renderUserPrompt`（镜像竞品 PromptService）。
- `listedIndustryRecommendAi.js`：resolve 模型 + `llmInvoke` + 解析 JSON。
- `initPrompts`（或估值 seed）注册上述种子，并尽量绑定已有/新建的 `project_valuation` 模型 id（解析逻辑同 initPrompts 里竞品/项目挖掘分支）。

## 6. 名单合并（必须改现逻辑）

现状：`replaceCaseComparables` 先软删本案件全部有效行再插入。从竞品刷新会丢掉手工/Excel/推荐行，也会复活用户刚删的代码。现网「竞品加载」前端是 preview 后 `PUT` 整表可勾选列表。

改为 **按 `stock_code` 合并**。不做 `user_edited` 列。

**复活哪一条：** 同案件同码多条软删时，取 `F_LastModifyTime` **最新**一条复活；其余同码软删保持删除（清理可放 P2）。

| 场景 | 已在有效名单 | 本案件曾软删 | 全新代码 |
|------|----------------|--------------|----------|
| 从竞品分析加载（专用接口） | 不刷业务字段；只补空展示字段 | **不复活** | 按 preview 行插入：`source=competitor_run`，带分/档位/勾选等 |
| 行业/赛道推荐确认 | 跳过 | 弹窗标「曾删除」，用户勾选才复活：按新分重置 `source`/`relevance_score`/`match_reason`/可比档位，`selected=1`，`in_pool` 按 ≥60，**清空底稿 PE/PS** | 插入 `source=industry_recommend`（`selected=1`，`in_pool` 按 ≥60） |
| 手工添加 | 提示已存在，不重复插、不改字段 | 复活最新软删行：保留勾选/档位/入池/底稿覆盖；`source=manual`（**禁止**再 INSERT 一条同码有效行） | 插入 `manual` |
| Excel 导入 | 同上 | 复活：保留旧设置；`source=excel` | 插入 `excel` |

底稿 PE/PS 覆盖：合并「保留」仅适用于手工/Excel 复活与竞品已在名单；**改码、推荐复活清空**。

**不提供**「完全替换名单」。删除语义只在 `DELETE`。

## 7. 数据与接口

`valuation_case_comparable` 增量：

- `source` 增加 `industry_recommend`（注释一并改）
- `match_reason VARCHAR(255) NULL` — 推荐匹配说明摘要（规则；可含已返回的 AI 业务句）
- P1.5：`match_reason_json JSON NULL` — 分维结构（行业/赛道标签/透镜/业务·AI）
- **不加** `user_edited`

接口（均挂现有案件权限）：

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/cases/:id/comparables/recommend/runs` | **发起推荐 run**（须当前草稿）。body：`relax`、`include_neeq`、`limit`。防抖/running 中返回 409 或 `accepted:false`。异步执行：规则+AI → 写 `valuation_case_recommend_run`。超时见环境变量（默认 5 分钟） |
| GET | `/cases/:id/comparables/recommend/runs` | 列表（含 status、version_no、时间）；默认最近若干条 |
| GET | `/cases/:id/comparables/recommend/runs/:runId` | 单版详情（success 才含完整候选）；供「查看本次推荐」 |
| GET | `/cases/:id/comparables/recommend/runs/latest` | 最新 success（或当前 running 状态，供按钮红/绿） |
| POST | `/cases/:id/comparables/recommend/runs/:runId/apply` | body：`stock_codes[]`。须 **当前草稿** + 该版 **success**。求交后合并进名单；`selected=1`，`in_pool` 按分 ≥60；写 `match_reason` |
| POST | `/cases/:id/comparables/recommend/ai-enrich` | **内部/可被 run 编排调用**；一般不由前端单独点。P1 起与 run 同生命周期 |
| POST | `/cases/:id/comparables/from-competitor` | 竞品加载专用合并 |
| PATCH | `/cases/:id/comparables/:cid` | 现有字段 + `stock_code`… |
| DELETE | `/cases/:id/comparables/:cid` | 软删 |
| PUT | `/cases/:id/comparables` | 手工规则 upsert；缺席不删；不承担竞品/推荐 |

> 原同步 `GET/POST .../comparables/recommend` 预览接口 **改为 run 模型**；若保留 GET 仅作内部调试，产品路径以 runs 为准。

表增量：

- `valuation_case_comparable`：`source=industry_recommend`、`match_reason`；可选 `match_reason_json`、`recommend_run_id`（溯源从哪一版确认）
- **`valuation_case_recommend_run`**：版本头 + 参数 + 状态 + 结果（或子表 `valuation_case_recommend_item`）

P0 前端：（竞品/编辑删除等同前，略）

P1 前端补充：

- 推荐按钮红/绿态；进度弹窗可关；「查看本次推荐」；防抖；版本切换（最近 5 成功版）。

模块建议：`listedIndustryRecommend.js` + `listedIndustryRecommendPrompt.js` / `listedIndustryRecommendAi.js` + `listedIndustryRecommendRunner.js`。不复用竞品 `prompt_type` / `competitor_match`。

## 8. 与相邻功能的边界

- **竞品分析关系表**：不改召回配额、金标、境内身份。推荐只服务估值可比名单。
- **竞品证据四维 / AI 对标综合分**：不复用为估值推荐分或理由骨架。估值侧自建「行业/赛道/透镜/业务」理由；AI 只补业务人话，不产出另一套综合分。
- **AI 配置边界**：估值推荐只用 `项目估值` / `project_valuation` 提示词与模型；后台改配置即生效。不占用竞品分析提示词额度语义，不改竞品 `initPrompts` 种子（仅新增估值条目）。
- **方法配置「申万三级中位数」**：仍是行业法倍数，不是个股名单；推荐 **借用草稿 `sw_industry_l3`**（有值即用），不把行业法成分股整表灌进可比名单。
- **估值说明**（`ValuationMethodGuide` 步骤 2）：功能上线后再改文案，补「可按行业/赛道推荐；行内可编辑删除；预览可见匹配理由」。
- **采集/计算**：仍只处理 `selected=1` 且无 `disabled_reason` 的境内代码。
- **草稿/正式版**：推荐发起与 apply **仅当前草稿**（与采集计算一致）；正式版不 apply。

## 10. 验收

1. 有四大类 + 标签的投后案件，点推荐能出同赛道 A 股，不含港美、不含标的自身；默认不含新三板、不含名称含「退市」；ST 可以出现；有四大类时候选不靠「仅申万一级」层灌入。
2. 确认后原手工行仍在；重复代码不双份；已在名单的推荐行跳过且不改分/来源。**新加入/推荐复活行主表勾选列为已勾选**（`selected=1`），无需用户再点一次即可参与采集；弱匹配也勾选，但 `in_pool` 仅 ≥60。
3. 编辑代码成功改名并清空底稿覆盖；改成已存在有效代码失败；改成仅软删过的代码失败并提示手工/推荐加回。
4. 删除后采集/POOL 不再包含该公司；刷新后仍不在。手工添加可加回且保留旧入池/覆盖（复活最新软删行）；Excel 加回 `source=excel`；推荐勾选加回按新分重置并清空覆盖。
5. 「从最新成功竞品分析加载」走专用接口：已删代码不自动回来；已在名单行的勾选、可比、入池、底稿、source、分不被覆盖；**新码仍带竞品分/档位**（不是手工默认中）。
6. 无行业信息时有明确提示；放宽后仍可出候选或明确「宇宙内无匹配」。
7. 勾选「含新三板」后候选可含新三板；POST 夹带未出现在本次重跑结果集中的码被跳过并返回原因。
8. 草稿已有申万三级（即使倍数来源是个股 POOL）时，推荐匹配说明能体现三级命中；三级为空则无「同三级」加分。
9. 主表将可比程度从强改为弱后，POOL Switch **保持原状**（不自动关闭）。
10. 点推荐后出现可关闭的进度弹窗，按钮变红；关弹窗不取消任务；用户可继续其它操作。
11. 5 秒内重复点或 running 中再点 → 不启第二个 run；P1 无取消按钮；超过环境变量时限（默认 5 分钟）→ failed/timeout，按钮回默认。
12. 规则+AI（或 AI 降级）全部结束后按钮变绿，出现「查看本次推荐」；**此前不能打开选企业宽表**。
13. 宽表含匹配说明与企业简介（限高+悬停）；确认后自动勾选采集；主表有匹配说明摘要。
14. 每次推荐有 `version_no`；案件保留最近 5 个成功版，可切换查看再 apply。
15. 空名单可只靠行业推荐完成进名单；冷启动文案不要求先跑竞品。
16. 后台存在 `项目估值` / `valuation_comparable_business_reason`；无可用模型时业务维降级但规则版仍可 success。

17. 正式版本视图下不可发起推荐 / apply；须切回草稿或新版本（与采集计算一致）。
