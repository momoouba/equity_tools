# 可比与采集：行业/赛道推荐上市备选 + 名单编辑删除

> 入口：项目估值工作台 → **可比与采集** → 「可比上市公司」。  
> 实现前仅方案，不改业务代码。确认后再按文末分期落地。

## 1. 要解决什么

当前名单只有三条进数路径：从最新成功竞品分析加载、手工股票代码、Excel 导入。表格没有「操作」列，不能改代码/名称，也不能删行。

缺口：

1. 竞品分析召回的是融资事件/未上市主体为主；估值 POOL 需要的是 **A 股（含北交所/新三板）上市备选**。标的已有行业标签、四大类、申万赛道时，应能直接从上市主档里捞最接近的公司。
2. 分析师需要对名单做 **编辑、删除**，且后续「从竞品分析加载」不能把手工改过的行整表冲掉。

港股美股仍不入池（与现口径一致）。

## 2. 产品位置与交互

工具栏在「从最新成功竞品分析加载 / 手工代码 / 添加 / Excel 导入」之后增加：

| 按钮 | 行为 |
|------|------|
| **按行业/赛道推荐** | 打开预览弹窗，勾选后合并进当前名单 |
| （表格）**操作：编辑 / 删除** | 行内改代码或可比属性；软删 |

推荐弹窗要点：

- 顶部展示本次用到的标的画像：四大类、申万路径、行业标签、透镜关键词（有则显示，无则空）。
- 表列：勾选、代码、名称、市场、四大类、申万三级、匹配分、匹配说明、状态（已在名单 / 曾删除 / 可新增）。
- 默认勾选：匹配分 ≥ 60 且尚未在名单中的前 15 家；已在名单的行勾选禁用，文案「已在名单」。
- 确认只 **按代码合并新增**，不整表替换。
- 画像不足（无四大类、无申万、无标签、无透镜词）时 Alert：「标的缺少行业/赛道信息，推荐会很宽或无法过滤。可先在竞品分析主体档案补标签，或改用手工/Excel。」仍允许点「放宽推荐」（仅按四大类或仅按申万一二级）。

编辑弹窗：

- 可改：股票代码、可比程度、是否入池、是否勾选。
- 代码失焦后走现有 `ipo_new_share` 解析，回填名称、市场、信用代码；解析失败或港美股则禁止保存。
- 名称、市场只读（以主档为准）。
- 改代码：新代码已在本案件有效名单中则拒绝；旧行财报按代码存在公共表，不随行迁移。

删除：

- 二次确认：「删除后不再进入采集与 POOL。可用手工代码或推荐再次加回。」
- 软删 `F_DeleteMark = 1`。勾选关闭、入池关闭不替代删除。

表格现有列保留，末尾加 **操作**；「说明」继续表示不可用原因（无代码、港美股等）。匹配理由另列 **匹配说明**（可先省略，悬停看全文）。

## 3. 标的画像从哪来

按估值案件类型取主体，字段做并集，后者只填前者空缺：

| 优先级 | 来源 | 字段 |
|--------|------|------|
| 1 | 投后 `invested_enterprises` / 投前 `sourcing_pre_investment_project` | `industry_category_4`、`sw_industry_l1/l2`、`ai_industry_tags_json` / `display` |
| 2 | 最近一次成功竞品 run 的 `S0_profile` | 四大类、申万、标签快照 |
| 3 | 竞争透镜 `competition_lens_json` | `must_align`、`custom_keywords`（短语加分，不单独当硬过滤） |
| 4 | 融资主档（信用代码对齐） | `industry_category_4`、`industry_std_lv1/lv2` |

不按具体公司名写死规则。标的若已上市，候选中排除自身（同一信用代码，或同一 `stock_code`）。

## 4. 上市宇宙与召回

宇宙：`ipo_new_share`，交易所 ∈ 上交所 / 深交所 / 北交所 / 新三板；排除港美。  
行业：表内 `sw_industry_l1/l2`、`industry_category_4`、`industry_tags_*`；缺三级时左连 `valuation_sw_constituent`（东财 EM2016）。  
四大类映射继续用 `sw_industry_category_map`，与竞品 Stage 1c 同一套。

召回漏斗（由窄到宽，每层凑够 `limit` 就停）：

1. 同 `industry_category_4` **且** 申万三级相同（有三级时）
2. 同四大类 **且** 申万二级相同
3. 同四大类
4. 仅申万一级相同（标的四大类为空，或第 3 层不足 10 家时）

每层再按第 5 节打分排序，去重后取 Top **30**（接口 `limit` 默认 30，最大 50）。

## 5. 匹配分（写入「综合分」）

0–100，与现网 `comparabilityFromScore` 对齐：≥80 强、≥60 中、否则弱；中/强默认入池。

| 项 | 分 | 说明 |
|----|----|------|
| 四大类相同 | +25 | 标的无四大类则 0，不扣 |
| 赛道/sub_track 相同 | +15 | 半导体 vs 先进制造等 |
| 申万三级相同 | +30 | 否则二级 +18，否则一级 +8 |
| 标签重叠 | 0–20 | 标的 AI 标签 vs 上市 `industry_tags_*`，Jaccard×20 |
| 透镜短语命中 | 0–15 | `must_align` / `custom_keywords` 出现在上市标签或产品/公司简介 |

匹配说明拼人话，例如：`四大类=生物医药；申万三级=化学制药；标签重叠 2/5`。  
推荐写入 `source = industry_recommend`，`relevance_score` = 匹配分。

这不是竞品分析综合分，不跑证据四维。同一行若先由竞品加载、后又被推荐命中：**不覆盖**已有综合分与来源。

## 6. 名单合并（必须改现逻辑）

现状：`replaceCaseComparables` 先软删本案件全部有效行再插入。从竞品刷新会丢掉手工/Excel/推荐行，也会复活用户刚删的代码。

改为 **按 `stock_code` 合并**：

| 场景 | 已在有效名单 | 本案件曾软删 | 全新代码 |
|------|----------------|--------------|----------|
| 从竞品分析加载 | 保留勾选、可比程度、POOL、底稿覆盖、source；只补空的名称/市场 | **不复活** | 插入 `source=competitor_run` |
| 行业/赛道推荐确认 | 跳过 | 弹窗标「曾删除」，用户勾选才复活 | 插入 `source=industry_recommend` |
| 手工 / Excel | 提示已存在，不重复插 | 复活该行并 `source=manual` | 插入 `manual` / `excel` |

底稿 PE/PS 覆盖始终跟代码走，合并时保留。  
增加 `user_edited`：编辑弹窗保存后置 1；竞品刷新不得覆盖该行的代码、勾选、可比程度、入池。

## 7. 数据与接口

`valuation_case_comparable` 增量：

- `source` 增加 `industry_recommend`（注释一并改）
- `match_reason VARCHAR(255) NULL` — 推荐/竞品匹配说明
- `user_edited TINYINT(1) NOT NULL DEFAULT 0`

接口（均挂现有案件权限）：

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/cases/:id/comparables/recommend` | 预览，query：`limit`、`relax=1` |
| POST | `/cases/:id/comparables/recommend` | body：`stock_codes[]`，合并插入 |
| PATCH | `/cases/:id/comparables/:cid` | 现有字段 + `stock_code`（改代码重解析） |
| DELETE | `/cases/:id/comparables/:cid` | 软删 |

`PUT /cases/:id/comparables` 改为调用合并，或前端不再整表 PUT、改走推荐/手工/PATCH。竞品「加载」确认后只提交新增代码 + 需要更新的竞品来源行。

模块建议：`news/server/utils/valuation/listedIndustryRecommend.js`，主体画像复用竞品已有标签解析，不复制策略文件。

## 8. 与相邻功能的边界

- **竞品分析关系表**：不改召回配额、金标、境内身份。推荐只服务估值可比名单。
- **方法配置「申万三级中位数」**：仍是行业法倍数，不是个股名单；推荐是给个股 POOL 备选。
- **估值说明**（`ValuationMethodGuide` 步骤 2）：功能上线后再改文案，补「可按行业/赛道推荐；行内可编辑删除」。
- **采集/计算**：仍只处理 `selected=1` 且无 `disabled_reason` 的境内代码。

## 9. 分期

**P0 名单可维护（先做）**

- 操作列：编辑弹窗、删除确认
- DELETE；PATCH 支持改代码
- 竞品加载改为按代码合并，不再整表替换

**P1 推荐**

- 画像组装 + 漏斗召回 + 打分
- 预览弹窗 + 确认合并
- `match_reason` / `user_edited` / `industry_recommend`

**P2 体验（可后置）**

- 表列「来源」「匹配说明」
- 推荐弹窗筛选：只看某四大类 / 只看某申万三级
- 曾删除代码一键清空（管理用）

## 10. 验收

1. 有四大类 + 标签的投后案件，点推荐能出同赛道 A 股，不含港美、不含标的自身。
2. 确认后原手工行仍在；重复代码不双份。
3. 编辑代码成功改名；改成已存在代码失败。
4. 删除后采集/POOL 不再包含该公司；手工添加可加回。
5. 再点「从最新成功竞品分析加载」，已删代码不自动回来，已编辑行不被覆盖。
6. 无行业信息时有明确提示，放宽后仍可出候选或明确「宇宙内无匹配」。

## 11. 确认后再实现的点

- 推荐默认勾选阈值：匹配分 ≥ 60 的前 15 家，是否改为「全部默认勾选、由用户去掉」。
- 新三板是否进推荐宇宙（采集已允许；若样本噪音大可默认排除、勾选「含新三板」）。
- 竞品加载是否提供「完全替换名单」危险操作（默认关闭）。
