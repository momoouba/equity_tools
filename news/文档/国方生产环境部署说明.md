# 国方生产环境部署说明

## 1. 服务器现状与部署架构

本文档基于当前生产机（华为云 ECS）实际状态整理，用于日常运维、版本更新和故障排查。

### 1.1 磁盘与目录规划

- 系统盘：`/dev/sda1` 挂载到 `/`
- 数据盘：`/dev/sdb1` 挂载到 `/data`（已配置开机自动挂载）
- 业务目录：`/opt/newsapp/news`
- 已迁移到数据盘的业务目录：
  - `/opt/newsapp/news/backups -> /data/newsapp/backups`
  - `/opt/newsapp/news/logs -> /data/newsapp/logs`
  - `/opt/newsapp/news/uploads -> /data/newsapp/uploads`
- Docker 数据目录：`/data/docker`（`Docker Root Dir` 已切换）

### 1.2 运行中的核心容器

- `newsapp-nginx`：Nginx 反向代理与静态资源服务
- `newsapp`：应用服务（Node/Express）
- `newsapp-mysql`：MySQL 8.0

常用检查命令：

```bash
docker ps
docker info | grep "Docker Root Dir"
df -h | grep -E "/$|/data"
```

## 2. 每月巡检清单（1分钟版）

每月至少执行一次，建议固定在每月第一周。

### 2.1 巡检命令

```bash
# 1) 磁盘总览（重点看 / 与 /data）
df -h

# 2) 系统盘最大目录（定位增长点）
sudo du -xhd1 / | sort -h

# 3) /var 占用（常见增长区）
sudo du -xhd1 /var | sort -h

# 4) Docker 占用与可回收空间
docker system df

# 5) 线上容器健康状态
docker ps
```

### 2.2 关注阈值

- `/` 使用率 > 75%：预警，排查增长来源
- `/` 使用率 > 85%：告警，立即清理可回收 Docker 资源
- 容器状态不是 `healthy`：优先处理服务可用性

### 2.3 快速清理命令（不停机优先）

```bash
docker builder prune -a -f
docker image prune -a -f
docker container prune -f
docker system df
df -h
```

> 注意：以上命令仅清理未使用资源，不会删除正在运行容器。

## 4. 日常更新操作（前端 / 后端）

以下流程基于现网当前部署方式，默认在 `cd /opt/newsapp/news` 目录执行。

## 4.1 只更新后端（server）

后端代码通过挂载生效，通常只需重启应用容器：

```bash
cd /opt/newsapp/news
docker compose restart app
docker compose logs -f app
```

验证：

```bash
docker compose ps
curl http://localhost:3001/api/health
```

## 4.2 只更新前端（client）

前端必须先构建，再把构建结果同步到前端 volume，然后重启 nginx。

### 方式 A：本地构建并上传（推荐）

本地：

```powershell
cd E:\USER\SUREAL\Desktop\equity_news\news\client
npm run build
```

上传 `dist` 到服务器 `/tmp/dist` 后，服务器执行：

```bash
cd /opt/newsapp/news
VOLUME_PATH=$(docker volume inspect news_app_frontend | grep -i "Mountpoint" | awk '{print $2}' | tr -d '",')
sudo rm -rf "$VOLUME_PATH"/*
sudo cp -r /tmp/dist/* "$VOLUME_PATH/"
docker compose restart nginx
```

### 方式 B：服务器上构建

```bash
cd /opt/newsapp/news/client
npm install
npm run build
cd ..
VOLUME_PATH=$(docker volume inspect news_app_frontend | grep -i "Mountpoint" | awk '{print $2}' | tr -d '",')
sudo rm -rf "$VOLUME_PATH"/*
sudo cp -r client/dist/* "$VOLUME_PATH/"
docker compose restart nginx
```

## 4.3 同时更新前后端

建议顺序：先前端构建/同步，再重启 app 和 nginx。

```bash
cd /opt/newsapp/news

# 1) 更新前端（示例：服务器构建）
cd client && npm run build && cd ..
VOLUME_PATH=$(docker volume inspect news_app_frontend | grep -i "Mountpoint" | awk '{print $2}' | tr -d '",')
sudo rm -rf "$VOLUME_PATH"/*
sudo cp -r client/dist/* "$VOLUME_PATH/"

# 2) 重启后端与 nginx
docker compose restart app nginx

# 3) 验证
docker compose ps
docker compose logs app --tail 30
```

## 5. 需要重建镜像的场景

出现以下情况时，不是 `restart`，而是要 `build`：

- 修改了 `Dockerfile`
- 修改了依赖文件（如 `package.json`、`requirements.txt`）
- 新增了 Python 依赖（例如 `pandas`、`akshare`）
- 需要强制更新镜像层或清理构建污染

执行方式（保留数据）：

```bash
cd /opt/newsapp/news
docker compose down
docker compose build --no-cache
docker compose up -d
docker compose ps
```

## 7. 常见问题与处理

### 7.1 前端已更新但页面仍旧

1. 检查是否已复制到前端 volume  
2. 重启 `nginx` 容器  
3. 浏览器强刷（Ctrl + F5）

### 7.2 后端更新后接口未生效

1. 检查是否重启了 `app`  
2. 查看 `docker compose logs app --tail 100`  
3. 确认更新路径是否在 `server` 挂载目录

### 7.3 系统盘又开始增长

优先执行：

```bash
docker system df
docker builder prune -a -f
docker image prune -a -f
df -h
```

## 9. 应急回滚流程（值班必备）

以下流程分为两档：  
- 30 秒快速回滚：适合“发布后立即报错/健康检查失败”  
- 5 分钟稳定回滚：适合“版本问题明显，需要回到上一个可用状态”

### 9.1 回滚前统一动作

```bash
cd /opt/newsapp/news
docker compose ps
docker compose logs app --tail 80
docker compose logs nginx --tail 80
```

先确认是应用问题还是环境问题，再选择回滚级别。

### 9.2 30 秒快速回滚（优先）

适用场景：
- 刚重启/刚发布就异常
- 容器状态异常但镜像与配置未改动

执行：

```bash
cd /opt/newsapp/news
docker compose restart app nginx
docker compose ps
curl http://localhost:3001/api/health
```

如果仅前端异常（白屏/资源404），可单独处理：

```bash
docker compose restart nginx
```

### 9.3 5 分钟稳定回滚（镜像级）

适用场景：
- 新版本镜像/依赖变更导致功能异常
- 需要切回上一版镜像

建议做法：
1. 在 `docker-compose.yml` 中把 `app` 镜像标签改回上一版（建议平时保留版本标签）  
2. 执行：

```bash
cd /opt/newsapp/news
docker compose down
docker compose up -d
docker compose ps
docker compose logs app --tail 100
```

如果没有版本化标签、只用 `latest`，建议先补镜像标签管理后再做高频发布。

### 9.4 Docker 数据目录回滚（仅迁移异常时使用）

当前标准目录为 `/data/docker`。如迁移后出现 Docker 无法正常工作，可回滚到 `/var/lib/docker`：

```bash
sudo systemctl stop newsapp-compose.service
sudo systemctl stop docker
sudo systemctl stop containerd

sudo rm -f /etc/docker/daemon.json
sudo rm -rf /var/lib/docker
sudo mv /var/lib/docker.bak /var/lib/docker

sudo systemctl start containerd
sudo systemctl start docker
sudo systemctl start newsapp-compose.service
```

验证：

```bash
docker info | grep "Docker Root Dir"
docker ps
```

### 9.5 业务数据目录回滚（软链异常时使用）

如 `logs/uploads/backups` 软链配置异常，可恢复原目录：

```bash
# 以 logs 为例
rm /opt/newsapp/news/logs
mv /opt/newsapp/news/logs.bak /opt/newsapp/news/logs
```

其他目录同理：
- `uploads`
- `backups`

### 9.6 回滚后验收清单

```bash
docker compose ps
docker compose logs app --tail 50
docker compose logs nginx --tail 50
curl http://localhost:3001/api/health
df -h | grep -E "/$|/data"
```

验收通过标准：
- 核心容器均为 `Up` 且 `healthy`
- 健康检查接口返回正常
- 页面可访问、核心功能可用
