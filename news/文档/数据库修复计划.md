db.js 中保留旧列名的位置均为:
- `migrateBatchFColumns` 迁移配置（`old: 'xxx'` 映射，必须保留旧名）
- CREATE TABLE IF NOT EXISTS 语句（首次安装时创建，之后由迁移函数处理）
- 迁移代码中的 `ADD COLUMN` / `CHANGE COLUMN`（兼容性逻辑）
- 种子数据 INSERT（在迁移前运行，必须用旧列名）

### 三、修改规范

**SQL 语句中的列名**: 直接替换为新名

```js
// 修改前
`SELECT id, stock_code FROM ipo_new_share WHERE delete_mark = 0 ORDER BY created_at DESC`

// 修改后
`SELECT F_Id, stock_code FROM ipo_new_share WHERE F_DeleteMark = 0 ORDER BY F_CreatorTime DESC`
```

**SQL 别名保持前端兼容**: 当 API 返回给前端时使用 `AS` 别名

```js
`SELECT F_Id AS id, stock_code FROM ipo_new_share`
```

**JS 属性访问**: 与 SQL 结果列名保持一致

```js
// SQL 不使用别名时，JS 需用 F_ 属性名
if (existing[0].F_DeleteMark === 1) { ... }

// SQL 使用别名时，JS 可保持旧名
// SQL: SELECT F_DeleteMark AS delete_mark FROM ...
// JS:  existing[0].delete_mark
```
