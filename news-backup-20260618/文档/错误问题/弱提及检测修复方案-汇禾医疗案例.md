## 弱提及检测修复方案 - 汇禾医疗误关联问题

### 问题回顾

新闻"强生起诉顺美医疗IVL专利侵权"被错误关联到汇禾医疗。文章主体是强生/Shockwave起诉顺美医疗，汇禾医疗仅在后半段作为国产IVL突围路径的三个例子之一被一笔带过（"汇禾医疗 C-Wave® 采用螺旋排布电极..."）。

### 根因分析

系统存在两个漏洞导致列举式提及的企业被保留关联：

**漏洞1：新榜接口的"免检通道"** — `processNewsWithEnterprise` 中，当新榜接口的企业已在 `invested_enterprises` 表中时（`shouldValidate = false`），直接跳过所有AI验证和提及权重分析，导致即使企业仅被顺带提及也不会被过滤。

**漏洞2：二次验证只看"名字是否出现"** — `analyzeEnterpriseRelevance` 的二次验证只检查企业全称/简称是否在全文中出现（`fullContent.includes()`），不区分"主体提及"和"列举提及"。只要名字出现一次就通过验证。

### 修复方案（3处代码修改）

**修改1：新增 `detectWeakMention` 独立方法**

从 `validateExistingAssociation` 中提取提及权重分析逻辑为独立方法，供所有处理路径共用。判定逻辑：企业名仅出现1次 + 不在标题 + 不在文章开头300字 + 文章长度>1500字 → 判定为弱提及（列举式/顺带提及）。

位置：`_caseInsensitiveMatch` 方法之后（约第5086行）

**修改2：`analyzeEnterpriseRelevance` 二次验证增加弱提及检测**

在现有的名称匹配检查之后、最终过滤之前，加入 `detectWeakMention` 调用。若判定为弱提及，将相关度降至10%（低于30%阈值，会被过滤掉）。

位置：二次验证的 `.map()` 回调末尾（约第5412行）

**修改3：`processNewsWithEnterprise` 增加全局弱提及检测**

在 `shouldValidate` 逻辑块之后、情绪分析之前，对所有路径（包括 `shouldValidate = false` 的新榜免检通道）执行弱提及检测。若判定为弱提及，解除企业关联。

位置：`shouldValidate` 块之后（约第6368行）

### 用汇禾医疗案例验证

修复后的处理流程：

1. 新闻进入 `processNewsWithEnterprise`，新榜接口 + 汇禾医疗在被投企业表中 → `shouldValidate = false` → 跳过AI验证（和之前一样）
2. **新增**：进入弱提及检测 → `detectWeakMention` 被调用
3. 核心关键词"汇禾医疗"在全文中的统计：提及次数=1，不在标题=是，不在开头300字=是，文章长度>1500字=是
4. 判定结果：弱提及 → 解除关联

### 注意事项

- 修改仅涉及 `server/utils/newsAnalysis.js`，无数据库变更，无提示词变更
- 语法检查已通过（`node -c`）
- 对已有的 `validateExistingAssociation` 路径（企查查/上海国际集团接口）无影响，该路径本身就包含提及权重分析
- 建议部署后观察日志中 `[detectWeakMention]` 标签的输出，确认判定准确性
- 如果发现某些合法关联被误判为弱提及，可以调整 `detectWeakMention` 中的阈值参数（如 `contentLength > 1500` 或 `mentionCount <= 1`）
