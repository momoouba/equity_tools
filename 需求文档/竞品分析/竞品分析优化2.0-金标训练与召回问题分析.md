# 竞品分析优化 2.0：金标训练、规则泛化与召回问题分析

> 针对 2026-07-15 以「上海未来不远机器人科技有限公司」为目标的跑批结果，结合《优化改进 2.0 需求.md》进行问题定位与改进建议。

## 1. 测试现象摘要

跑批配置：

- 目标：上海未来不远机器人科技有限公司，透镜已确认，`must_align` 含「面向家庭场景的具身智能服务机器人」「C 端家庭用户」「轮式双臂」「家庭通用机器人」。
- 召回：`use_new_share_listed_recall: false`，内部召回 3850 条（`ipo_project` 899 + `sourcing_financing_event` 2996）。
- S2 规则分 Top 出现「深圳地瓜机器人」（internal 85）、「鹿明机器人」（86）等高 buzzword 候选。
- S3：`form_unlisted_boost = 0`，未上市同形态候选未进入 LLM 池；LLM 池大小 28。
- S4：联网发现 17 条，返回 1X、求之、自变量、Figure、Mentee、星灿、银河通用等；但**诺因、欧拉、破壳等金标同形态早期公司未召回**。
- S5：最终落库 17 条，多数来自 `ai_web`；内部规则候选（如深圳地瓜）被 S5 判定为 upstream_downstream 剔除，但已浪费 LLM 调用。

核心矛盾：**真正该出现的早期同形态竞品进不来，靠 S4 联网“赌命”；规则分又高噪，导致 LLM 池里混进大量上游/跨层候选。**

## 2. 根因拆解

### 2.1 S1 内部召回：早期未上市公司不在库，且未切 new_share 上市源

当前跑批 `use_new_share_listed_recall: false`，上市侧仍用 `ipo_project`（基金底层项目，仅约 1100 家），未启用 `ipo_new_share` 全市场约 4773 家上市公司。对「未来不远」这类早期公司，真正的 direct 竞品（诺因、欧拉、破壳等）多为 2025–2026 年成立、未进入 `sourcing_financing_event` 的极早期公司，内部 DB 本来就没有。

`recallFinancingByProductTerms` 会用透镜关键词做 `LIKE` 召回（`server/utils/competitor-analysis/competitorMatchRecall.js:212`），但召回前提是候选已存在于融资表。对于尚未入库的早期公司，SQL 召回无能为力。

### 2.2 S2 规则分：硬编码锚点 + 短 buzzword 导致虚高

`competitorProductLineUtils.js:280-282` 的 `buildLensScoringAnchors` 中写死了机器人相关短锚点：

```js
/(?:消费级|家用|家庭|通用|C端)?(?:服务|智能)?机器人|教育陪玩|全能管家|家庭管家|家庭服务|C端商业化|C端家庭|长程任务|家务协作|双臂|轮式底盘/g
```

这会导致：

- 任何候选简介只要含「机器人」就能拿到较高 `formCustomerScore`；
- 深圳地瓜（RDK 套件/开发板）、跨维（开发平台/传感器）、正行创新（B 端零售系统）等因命中「机器人」而获得虚高的规则分。

同时 `scoreSpecificTagOverlap` 对 `具身智能 / AI / 大模型 / 机器人` 等 buzzword 仅降权到 0.2，而非直接剔除，仍然会让同 buzzword 但不同形态的候选进入 S3。

`ruleScoreCandidate`（`competitorAnalysisRunner.js:827-843`）还为融资池未上市候选提供额外 `+20` 的形态 boost：

```js
if (fromFinancing && !listedInternal && (formCustomerScore || 0) >= FORM_UNLISTED_LLM_MIN_FORM) {
  internalScore = Math.min(100, internalScore + Math.min(20, Math.round((formCustomerScore || 0) * 0.22)));
}
```

当 `formCustomerScore` 因短锚点被高估时，未上市的「伪竞品」会直冲 Top 20。

### 2.3 S3 入池门槛过低，规则噪音进入 LLM 池

`qualifiesForLlmPool`（`competitorAnalysisRunner.js:359`）当前规则：

- `internalScore >= 15` 即可入池；
- `coreLineScore >= 15` 即可入池；
- `tagScore >= 22` 即可入池；
- 赛道命中豁免只要 `internal >= 8`、`product >= 12`。

这些门槛对「机器人」这种高 buzzword 赛道太松。深圳地瓜 internal 85、跨维 internal 69 等都通过了 S3；而真正的 early-stage 同形态公司因为库内无数据进不来，反而上游/平台型公司占据 LLM 调用。

### 2.4 S4 联网发现：LLM 检索方差大，金标依赖不可控

`discoverWebCompetitors`（`competitorAnalysisAi.js:236`）完全依赖模型的联网能力。模型按 16 个关键词自主检索，返回结果受以下因素影响：

- 检索词是否覆盖公司别称/简称；
- 搜索引擎排序；
- 模型知识截止；
- 每次调用搜索策略不同。

诺因、欧拉、破壳等公司成立时间短、网络曝光低，模型检索到它们的概率本身就低。把金标召回寄托在 S4 上，等同于把系统性风险外包给 LLM 方差。

### 2.5 form_unlisted_boost = 0 的根因

`buildLlmScoringPool`（`competitorAnalysisRunner.js:477-505`）中，未上市候选要满足：

```js
form >= formMin // 透镜确认时 formMin = 22，否则 30
// 或
form >= formMin - 8 && core >= 16
```

`formCustomerScore` 基于目标透镜/核心产品线短锚点在候选文本中的匹配。诺因、欧拉、破壳如果库内简介里没有「轮式双臂」「家庭通用机器人」等长锚点，`form` 就为 0，自然触发不了 boost。

也就是说：**形态分对“未入库/简介稀疏”的早期公司过于严格，却对“含机器人一词”的平台型公司过于宽松。**

## 3. 通用规则训练与金标校准方案

### 3.1 建立金标数据集

延续需求文档 §4.1.1 的 `competitor_gold_standard_pair` 表，但这次把目标扩展到「同赛道多目标」：

- 每个 `category_4` / `sub_track` 组合选取 5–8 个目标企业；
- 每个目标人工标注 20–40 条候选（direct / indirect / same_track / upstream_downstream / non）；
- 覆盖已上市、未上市、早期、海外等多种形态；
- 字段：目标画像、候选画像、人工标签、当前 S2 各 feature、LLM 分、最终来源。

### 3.2 特征工程与可解释模型

对每条目标-候选 pair，计算稳定特征：

- `core_line_overlap`：核心产品线重叠（长度、权重、命中质量）；
- `form_customer_alignment`：形态/服务对象对齐（但需剔除 buzzword 短锚）；
- `specific_tag_overlap`：剔除 buzzword 后的具体标签 Jaccard；
- `industry_l1_match`、`category_4_match`；
- `structured_primary_product`、`structured_target_customer` 等字段匹配（Stage 3  structured 完成后）；
- `source_type`：上市/未上市/融资/联网。

建模：

- 二分类逻辑回归（L2）预测「是否竞品（direct/indirect/same_track）」；
- 对 `ai` 等 buzzword 重的赛道，正则化系数提高，避免过度拟合「机器人」；
- 输出每个特征的权重，可直接映射为代码里的权重/上限。

### 3.3 交叉项目验证与防过拟合

- **Leave-one-target-out**：每次留出一个目标作为测试集，其余训练；
- 若某目标上 F1 显著低于平均，说明规则在该子赛道过拟合；
- 对 `home embodied robot` 这类细分子赛道，单独建 `sub_track` 样本，而不是把所有机器人归为一类；
- 定期用「非金标目标」抽检，确保泛化。

### 3.4 将模型结果落地为代码阈值/权重

把模型学到的权重写入策略配置（如 `aiStrategy.ruleWeights`），而不是写死常数：

```js
// 示例：策略配置
aiStrategy.ruleWeights = {
  product: 0.25,
  coreLine: 0.35,
  formCustomer: 0.25,
  specificTag: 0.10,
  industry: 0.05,
};
```

对 `ai` 赛道，额外约束：

- 若候选 `looksLikeEmbodiedBrainOnly` 且目标 `looksLikeHomeEmbodiedRobot`，`formCustomerScore` 上限 35；
- 若候选 `looksLikeIndustrialRobot` 且目标 `looksLikeHomeEmbodiedRobot`，`formCustomerScore` 上限 25；
- 仅当存在非 buzzword 形态锚点命中时，才允许融资池未上市 boost。

## 4. 代码层改进建议

### 4.1 修复 S2 规则泛化性

1. **移除/参数化硬编码锚点**：把 `competitorProductLineUtils.js:280-282` 的机器人锚点正则改为配置驱动，或仅在确认透镜中由用户自定义关键词生成，禁止在通用函数里写死赛道词。
2. **彻底剔除 buzzword 在形态分中的贡献**：
   - 在 `scoreFormCustomerAlignment` 中，将 `lensLines` 里的 `isTechBuzzwordTag` 和 `isGenericIndustryTag` 全部过滤；
   - `scoreSpecificTagOverlap` 中，对 `isTechBuzzwordTag` 设权重为 0，而不是 0.2。
3. **融资池未上市 boost 加形态锚点质量校验**：只有在命中至少一个「具体产品形态锚点」（≥6 字，非 buzzword）时才给 boost。

### 4.2 收紧 S3 入池门槛

修改 `qualifiesForLlmPool`（`competitorAnalysisRunner.js:359`）：

- `internalScore` 门槛从 15 提高到 22（`ai` 赛道可配置）；
- 删除 `tagScore >= tagMin` 单独入池路径，改为 `specificTagScore >= tagMin AND (formCustomerScore >= 15 OR coreLineScore >= 12)`；
- 赛道命中豁免：`productScore >= 15`、`coreLineScore >= 12` 同时满足，并排除 `looksLikeEmbodiedBrainOnly`/`looksLikeIndustrialRobot` 等形态冲突。

### 4.3 增强 S1 未上市早期召回

1. **启用 `use_new_share_listed_recall`** 对 `ai` 赛道灰度，至少补齐上市侧候选（`competitorMatchRecall.js:484` 开关）。
2. **金标种子召回**：在 `buildInternalRecallPool` 中加入「金标同赛道候选」作为额外来源。对未入库的金标公司，先用企查查/名称搜索补一条轻量记录，再进入 S3/S5。
3. **联网关键词召回增强**：在 `recallFinancingByProductTerms` 中，对透镜关键词做同义扩展（如「轮式双臂」→「轮式」「双臂」「家庭机器人」「家用机器人」「双机械臂」），而不是只取字面 `LIKE`。

### 4.4 降低 S4 方差

1. **多轮检索**：对每批关键词做 2–3 轮不同角度检索（产品形态、创始人背景、融资阶段），合并候选，降低单次 LLM 遗漏。
2. **金标缺失检测**：S4 返回后，若金标库中同 sub_track 的公司未出现，触发一次「定向名称检索」：把金标名称作为 `excludeNames` 的反向列表，要求 LLM 专门检索这些公司是否存在。
3. **结构化 prompt**：让 LLM 按「direct / same_track / indirect / upstream_downstream」分类返回，并给出判定依据，便于后续规则后处理。

### 4.5 A/B 与开关

- 按需求文档 §8.3，所有改动走 `competitor_recall_source_config` 配置开关；
- 灰度目标：先在 `ai` 赛道 5–10 个案例跑 A/B，对比「新规则 vs 旧规则」的 F1、S4 依赖度、LLM 调用量；
- 指标：
  - 金标 recall@S5
  - 规则 Top 20 中最终 rejected 比例
  - S3 LLM 池中 downstream/upstream 比例
  - 平均每次跑批 LLM 调用数

## 5. 验证指标

| 指标 | 当前基线 | 目标 |
|------|----------|------|
| 金标 direct/same_track 召回率 | 依赖 S4，方差大 | ≥ 70% 不依赖 S4 |
| S3 规则 Top 20 最终 rejected 比例 | 较高（如深圳地瓜、跨维等） | ≤ 30% |
| S3 LLM 池上游/下游占比 | 较高 | ≤ 20% |
| 形态分 ≥22 的未上市候选数 | 0（form_unlisted_boost=0） | ≥ 3–5 |
| 跨项目 leave-one-out F1 | 未知 | ≥ 0.70 |
