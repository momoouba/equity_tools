## 二、融资数据入库后百科 + Enrich 逻辑检查

### 当前流程

```
新融资事件入库（financingIngestService.js）
  ├─ ① reuseFinancingAiForEventId() — 同企业已有 AI enrich → 直接复用（fan-out）
  ├─ ② enqueueIngestFinancingAiEnrich() — 无复用 → 异步 LLM 联网 enrich
  └─ ③ 百科查词 — ❌ 无自动触发，仅靠手动批处理脚本
```

### 评估结论

| 环节 | 是否合理 | 说明 |
|------|----------|------|
| AI enrich 自动触发 | **合理** | 入库时自动触发，有 donor 复用机制避免重复 LLM 调用 |
| AI enrich 增量处理 | **合理** | 已有 `ai_product_intro` 的不重复处理；donor 检查覆盖跨行/跨表复用 |
| 百科查词自动触发 | **❌ 缺失** | 新融资事件入库后**不会自动触发百科查词**，必须手动运行 `backfillFinancingBaikeLookup.js` |
| 百科查词增量处理 | **合理** | `skipLookedUp=true`（默认）跳过已查词企业，支持增量 |
| 已上市同步 | **合理** | `syncListedFinancingFromNewShare.js` 从 ipo_new_share 同步，设 `profile_source=listed_sync`，跳过后续 enrich |
| Enrich 降级逻辑 | **合理** | 有百科 → 结构化抽取；无百科 → LLM 联网（`profile_source=llm_web`，`confidence≤0.55`） |

### 需要补充

1. **百科查词缺少自动触发**：建议在新融资事件入库后（`financingIngestService.js`）增加百科查词的异步触发，类似 AI enrich 的 `enqueueIngestFinancingAiEnrich` 模式。或者设置定时任务（如每天凌晨）自动运行增量百科查词。
2. **百科 → structured 的衔接**：当前百科查词完成后，需要手动运行 `backfillFinancingProfileEnrich.js` 做结构化抽取。建议串联为自动流水线：百科完成 → 自动触发 structured。

## 三、「可比公司」标记与金标准标注

### 当前状态：两套独立系统，无直接关联

| 维度 | 可比公司标记（`include_in_comparable`） | 金标准标注（`competitor_gold_standard_pair`） |
|------|----------------------------------------|----------------------------------------------|
| 存储表 | `sourcing_competitor_relation` + `sourcing_competitor_comparable_pref` | `competitor_gold_standard_pair` |
| 用途 | 用户标记哪些竞品是"可比公司"，跨重跑保留偏好 | 3 人独立标注的目标-候选对，用于评测召回质量 |
| 写入方式 | 前端 PATCH 端点单用户操作 | 手动导出 CSV → 3 人标注 → 仲裁 → 导入 |
| 对召回的影响 | 无直接影响（仅保留用户偏好） | 金标准候选直接进入 S1 召回池（`recallGoldStandardCandidates`） |
| 对评测的影响 | 无 | 用于计算金标准竞品类型一致率（§9.3 指标） |

### 问题

**用户标记的「可比公司」没有自动进入金标准体系。** 这意味着：

1. 用户在日常使用中积累的可比公司判断（哪些是 direct/indirect/same_track）**被浪费**了，不能用于评测召回质量。
2. 金标准标注仍需从零开始的人工标注流程（导出 → 3 人标注 → 仲裁），无法利用已有的用户判断。
3. `competitor_gold_standard_pair` 表目前只能通过 `exportGoldStandardTemplate.js` 手动导入填充，没有从生产数据自动积累的机制。

### 建议

**建立「可比公司」→ 金标准的晋升通道**：

- 当同一竞品关系被 ≥2 个不同用户标记为可比（或同一用户标记后在重跑中持续保留），自动写入 `competitor_gold_standard_pair` 表，`status='auto_candidate'`。
- 后续由业务团队对这些 auto_candidate 记录做确认/仲裁，升级为 `status='done'` 的正式金标准。
- 这样可以在日常使用中逐步积累金标准数据，而非依赖一次性的大量人工标注。

#### 下一版本优化（P2，1-2 个月）

| 项 | 说明 |
|----|------|
| 可比公司 → 金标准晋升通道 | 自动积累标注数据，提升评测覆盖率 |
| 透镜版本号原子化 | 用 `UPDATE SET version = version + 1` 替代 JS 层递增 |
| 全局 cache 隔离 | 按 runId 分 namespace 或移入 transaction 内 |
| 关系列表分页 | 200 条硬限改为 cursor/offset 分页 |
| LLM 返回异常值防护 | `simResult.score ?? 0` fallback |
| 融资百科→structured 自动流水线 | 串联百科查词 → 结构化抽取为自动 pipeline |

### 总结

当前代码**可以上线**，但建议先修复 5 个 P0 项（约 2 天工作量），特别是 R-C1（category_4 死代码）和 A-C1（迁移端点无鉴权）影响最大。P1 项可在上线后 1-2 周内逐步修复。P2 项纳入下一版本规划。

融资数据流方面，AI enrich 的自动触发和增量处理已经合理，但**百科查词缺少自动触发**是一个明显的缺口，建议尽快补上。

可比公司标记与金标准是两套完全独立的系统，建议建立晋升通道，让日常使用中的用户判断能自动积累为金标准数据。
