## P0 — 上线前必须修复（约 2.5 天）

### Fix-01：`target.industry_category_4` 未赋值（R-C1）
- **文件**：`competitorAnalysisRunner.js` L806-824 `buildTargetProfile`
- **问题**：target 对象从未设置 `industry_category_4`，categoryScore 加分（权重 0.06）是死代码
- **修复**：在 `buildTargetProfile` 末尾调用 `resolveTargetCategory4`（来自 `industry-strategies/index.js`）赋值 `target.industry_category_4`
- **工作量**：0.5 天
- **需决策**：否

### Fix-02：S5 校验失败 fallback 过于宽松（R-C2）
- **文件**：`competitorAnalysisRunner.js` L1842-1849
- **问题**：校验异常时 fallback 为 `direct` + score=50，产生假阳性
- **修复**：改为 `competitor_type: 'same_track'`，`validated_score: 30`
- **工作量**：0.5 小时
- **用户决策**：降级为 same_track + 30 分
- **需决策**：否

### Fix-03：迁移端点无鉴权（A-C1）
- **文件**：`competitorMigrationRoutes.js` L15, L26, L45
- **问题**：3 个端点（GET/PUT config、POST run）无任何鉴权中间件
- **修复**：3 个端点均加 `requireAdmin` 中间件
- **工作量**：0.5 小时
- **需决策**：否

### Fix-04：comparable 和 bp-extract 缺归属校验（A-C2/A-C3）
- **文件**：`competitorMatchRoutes.js` L1062-1104, L1684-1722
- **问题**：PATCH comparable 和 POST bp-extract 未检查调用者是否有权操作
- **修复**：
  - comparable：加 `loadCompetitorRelationForWrite` 检查
  - bp-extract：加创建者/admin 检查（参考 L1643-1644 的 `isAdminUser` 模式）
- **工作量**：0.5 天
- **需决策**：否

### Fix-05：竞品分析运行无并发保护（A-C4）
- **文件**：`competitorMatchRoutes.js` L459-522, L1778-1847
- **问题**：同一企业/项目可同时触发多次分析
- **修复**：在插入 run 记录前，查询是否已有 `status='running'` 的 run，有则返回 409 Conflict
- **工作量**：0.5 天
- **用户决策**：拒绝新运行
- **需决策**：否

### Fix-06：透镜加载缺 F_DeleteMark 过滤（L-C1）
- **文件**：`competitionLensService.js` L671-673
- **问题**：`loadSavedCompetitionLens` 对 invested_enterprise 查询缺少 `AND F_DeleteMark = 0`
- **修复**：加 `AND F_DeleteMark = 0`
- **工作量**：10 分钟
- **需决策**：否

### Fix-13：融资入库时异步触发百科查词
- **文件**：`financingIngestService.js` L327-357 附近
- **问题**：新融资事件入库后不自动触发百科查词
- **修复**：

  2. 新增 `enqueueFinancingBaikeLookup({ eventId })` 函数，将百科查词任务入队
  3. 查词完成后 fan-out 到同企业的所有融资行（复用现有逻辑）
- **工作量**：1-2 天
- **用户决策**：入库时异步触发
- **需决策**：否

### Fix-14：可比公司标记自动写入金标准
- **文件**：`competitorMatchRoutes.js` L1062-1104（PATCH comparable 端点）、`competitorComparablePrefService.js`
- **问题**：用户标记可比公司与金标准完全独立
- **修复**：
  1. 在 `upsertComparablePrefForRelation` 成功后，检查 `include_in_comparable === true`
  2. 若为 true，自动在 `competitor_gold_standard_pair` 中 upsert 一条记录：
     - `final_is_competitor = 1`
     - `final_type` = 竞品关系中的 `competitor_type`
     - `status = 'done'`（用户已确认，无需额外标注）
     - `annotator_1_is_competitor = 1`，标注者 = 当前用户
  3. 去重：按 `target_credit_code + candidate_credit_code` 判断是否已存在
- **工作量**：1 天
- **用户决策**：1 个用户标记即可自动写入金标，无需业务确认
- **需决策**：否
