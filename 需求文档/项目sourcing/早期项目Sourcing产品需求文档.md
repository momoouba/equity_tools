# 早期项目Sourcing产品需求文档

# 一、产品概述

## 1\.1 产品定位

本产品是一款面向早期项目挖掘的Sourcing工具，核心功能是通过多渠道数据源抓取项目相关数据，经AI分析整合后形成标准化项目数据池，再根据项目发展阶段，向用户推送分阶段项目清单，辅助用户高效挖掘优质早期项目（重点聚焦AI领域），降低项目筛选成本，提升sourcing效率。

产品核心价值：打破多平台数据壁垒，自动化完成数据抓取、清洗、分析、分类，以分阶段推送的形式，为用户提供精准、全面的早期项目信息，同时支持赛道自定义划分与人工调整，适配用户个性化需求。

## 1\.2 核心目标

- 实现多指定数据源的自动化数据抓取、实时更新，形成结构化项目数据池；

- 通过AI分析，完成项目信息整合、赛道自动划分（基于用户自定义规则）、项目阶段判定；

- 按项目发展阶段，向用户推送包含完整信息的项目清单，满足不同阶段的sourcing需求；

- 支持用户自定义赛道划分、手动调整项目赛道信息，提升数据适配性。

# 二、核心需求梳理

## 2\.1 核心用户需求

用户核心诉求是“高效获取优质早期项目信息”，具体拆解为以下4点：

1. 数据全面性：覆盖指定多渠道数据源，获取项目、人员、投融资、技术、社交表现等多维度信息，无需手动跨平台查询；

2. 数据精准性：通过AI清洗、整合，过滤无效信息，确保项目信息完整、一致，赛道划分符合用户预期；

3. 推送及时性：按项目发展阶段（早期、投前、有融资/PR）自动邮件推送，第一时间获取项目动态；

4. 操作灵活性：支持用户自定义赛道划分规则，可手动修改项目赛道、补充项目信息，适配个性化sourcing需求。

## 2\.2 产品核心功能需求

- 多数据源自动化抓取与更新：覆盖企名片/犀牛、Github、Product Hunt、微信公众号、小红书/微信创业群、Google顶刊论文，实现数据实时抓取、定期更新；

- 数据池构建与管理：对抓取的数据进行清洗、结构化整理，形成包含项目、人员、投融资、赛道、平台表现等信息的标准化数据池；

- AI智能分析：基于用户自定义赛道规则，自动完成项目赛道划分；整合项目多平台表现，生成项目说明；判定项目发展阶段；

- 分阶段邮件推送：根据项目阶段（早期、投前、有融资/PR），推送对应维度的项目清单，包含同赛道其他公司对比信息；

- 前端交互与配置：支持用户自定义赛道划分规则、手动修改项目赛道及相关信息、查看数据池详情、配置邮件推送参数。

## 2\.3 非功能需求

- 稳定性：数据抓取服务7×24小时稳定运行，避免出现抓取中断、数据丢失，应对各平台反爬机制，保障数据获取连续性，可参考成熟数据抓取方案的反爬应对策略优化稳定性；

- 时效性：数据源更新后，抓取、清洗、分析、推送全流程不超过24小时（Google论文、小红书群消息等实时性需求较高的数据源，缩短至12小时内）；

- 准确性：AI赛道划分准确率不低于85%，项目信息清洗后错误率低于5%，可通过人工校验优化模型准确率；

- 安全性：用户数据、抓取数据加密存储，避免信息泄露；支持用户权限管理（仅自己可见自己的配置与推送内容）；

- 可扩展性：支持新增数据源、新增项目阶段、优化AI分析规则，适配后续业务拓展（如新增非AI领域赛道）。

# 四、核心功能模块详细说明

## 4\.1 数据抓取模块

### 4\.1\.1 抓取规则配置

- 支持用户配置各数据源的抓取范围（如微信公众号指定AI产业媒体列表、Github指定技术方向关键词、Google论文顶刊列表）；

- 可设置抓取频率、重试机制（抓取失败后自动重试，最多3次）、反爬应对策略（如模拟人工操作、IP轮换，参考成熟数据抓取的反爬方案）；

- 支持手动触发抓取（针对紧急需求，如某平台发布重要项目信息）。

### 4\.1\.2 数据清洗与结构化

- 自动过滤无效数据（如重复项目、空白信息、非AI领域无关项目）；

- 将抓取的非结构化数据（如公众号文章、群聊消息、论文摘要）转化为结构化数据，统一字段格式（如项目名称、简介、人员信息、平台表现等）；

- 数据去重规则：以“项目名称\+核心创始人”为唯一标识，避免重复入库；

- 异常数据处理：抓取失败、数据不完整的项目，标记为“待校验”，提醒用户手动补充或重新抓取。

## 4\.2 数据池管理模块

### 4\.2\.1 数据池结构

数据池包含5大核心数据表，关联项目全维度信息，适配AI分析及推送需求，结合AI产业分层逻辑优化数据分类：

1. 项目基础表：项目ID、项目名称、简介、核心亮点、数据源列表、入库时间、更新时间、项目阶段、所属赛道；

2. 人员信息表：人员ID、姓名、所属项目、职位、简介、关联平台（如Github账号、Product Hunt账号）、联系方式（如有）；

3. 平台表现表：项目ID、数据源、平台相关指标（Github标星数/增长、Product Hunt排名/投票数、公众号文章阅读量等）、指标更新时间；

4. 投融资信息表：项目ID、融资轮次、融资时间、投资机构、融资金额、PR信息链接；

5. 赛道配置表：赛道ID、赛道名称、赛道定义（用户自定义）、包含项目ID列表。

### 4\.2\.2 数据池操作

- 查看：支持用户按项目阶段、赛道、数据源、更新时间等条件筛选项目，查看项目完整信息；

- 编辑：支持用户手动修改项目信息（如赛道、简介、人员信息），修改后自动同步至AI分析模块，更新相关推送内容；

- 删除：支持用户删除无效、重复或不需要的项目，删除后同步移除相关关联数据；

- 导出：支持用户导出指定条件的项目数据（如某赛道所有早期项目），格式为Excel/Csv，适配用户后续分析需求。

## 4\.3 AI智能分析模块

### 4\.3\.1 赛道自动划分

- 规则配置：用户在前端页面自定义赛道划分规则（如赛道名称、赛道定义、关键词，例：“AI大模型”赛道定义为“聚焦LLM、多模态大模型研发的项目”，关键词：LLM、多模态、大模型），可参考AI产业基础层、技术层、应用层的分层逻辑进行划分；

- 自动判定：项目入库时，AI基于项目简介、亮点、技术方向、公众号标签等信息，匹配用户自定义赛道规则，自动将项目划分至对应赛道；

- 人工调整：用户可在前端页面手动修改项目所属赛道，修改后AI记录调整逻辑，优化后续自动划分准确率，形成“自动判定\+人工校准”的闭环。

### 4\.3\.2 项目阶段判定

AI基于数据池中的项目信息，自动判定项目所处阶段，判定规则如下，结合AI项目从技术研发到融资落地的生命周期特性优化判定逻辑：

1. 早期：仅具备产品原型、核心技术（如Github有代码、论文有相关研究），无明确融资信息、无PR曝光，重点标注产品核心功能与技术优势；

2. 投前：具备成熟产品/技术，有明确创始团队（人员信息完整），无融资信息或处于融资筹备阶段，补充核心团队背景分析；

3. 有融资/PR：已完成某一轮融资（投融资信息表有记录），或有相关PR报道（公众号、其他媒体），补充融资细节与PR核心信息；

4. 阶段更新：当项目数据更新（如新增融资、核心人员变动），AI自动更新项目阶段，同步调整后续推送内容。

### 4\.3\.3 项目说明生成

AI整合项目多维度信息，自动生成项目说明，包含以下内容，突出项目核心价值与潜力：

- 信息来源：列出项目所有抓取数据源（如“企名片\+微信公众号\+Github”）；

- 多平台表现：汇总各数据源的核心指标（如“Github标星500\+，近7天增长100\+；Product Hunt排名Top10，投票数200\+”）；

- 核心亮点：提炼项目产品、技术、团队优势（结合Github项目亮点、公众号介绍、论文研究方向）；

- 同赛道对比：提取同赛道其他项目的核心信息（如项目数量、头部项目、平均融资情况），辅助用户判断项目竞争力，参考AI产业各赛道发展现状补充对比维度。

## 4\.4 分阶段邮件推送模块

### 4\.4\.1 推送配置

- 用户配置推送邮箱、推送频率（如每日/每周推送，可选择具体推送时间）；

- 支持用户选择推送阶段（可单选或多选：早期、投前、有融资/PR）；

- 支持用户设置推送筛选条件（如指定赛道、指定数据源、项目热度阈值）。

### 4\.4\.2 推送内容规范

按项目阶段划分推送内容，每个阶段的项目清单包含“项目基础信息\+对应阶段核心信息\+项目说明”，格式统一、重点突出，具体如下：

1. 早期项目推送：
        

    - 核心内容：项目名称、简介、产品/技术亮点、数据源、AI生成的项目说明（重点突出产品原型、技术优势）；

    - 附加：无（仅聚焦产品、技术层面）。

2. 投前项目推送：
        

    - 核心内容：在早期项目内容基础上，增加“核心团队信息”（人员姓名、职位、简介）；

    - 附加：项目团队的行业背景分析（AI自动提炼）。

3. 有融资/PR项目推送：
        

    - 核心内容：在投前项目内容基础上，增加“投融资信息”（融资轮次、金额、投资机构）、“PR信息”（报道链接、核心内容）、“所属赛道”；

    - 附加：同赛道其他公司情况（核心项目对比、赛道整体趋势，结合AI产业赛道发展数据）。

### 4\.4\.3 推送提醒

- 新项目入库且符合推送条件时，触发邮件推送（实时推送可配置）；

- 项目阶段更新时，推送阶段更新提醒（如“XX项目从早期升级为投前阶段，补充团队信息”）；

- 推送邮件包含“查看详情”链接，点击可跳转至产品前端页面，查看项目完整信息及数据池详情。

## 4\.5 前端交互模块

### 4\.5\.1 赛道配置页面

- 支持用户新增、编辑、删除赛道，填写赛道名称、赛道定义、核心关键词；

- 展示所有赛道的包含项目数量、最近更新时间，支持按赛道名称搜索；

- 提供赛道划分规则参考（如AI产业常见赛道划分示例，结合基础层、技术层、应用层分类），辅助用户配置。

### 4\.5\.2 数据池查看页面

- 多条件筛选：支持按项目阶段、赛道、数据源、更新时间、热度指标（如标星数）筛选；

- 项目详情页：展示项目所有关联信息（基础信息、人员、平台表现、投融资、项目说明），支持编辑、删除、导出；

- 数据统计：展示数据池总项目数、各阶段项目数、各赛道项目数、各数据源项目数，以图表形式呈现（如柱状图、饼图）。

### 4\.5\.3 推送配置页面

- 邮箱配置：填写推送邮箱，支持验证邮箱有效性；

- 推送规则：选择推送阶段、推送频率、推送时间，设置筛选条件；

- 推送记录：查看历史推送记录（推送时间、推送内容、推送状态），支持重新推送。

# 五、用户操作流程

1. 初始化配置：用户注册登录后，先在前端配置赛道划分规则（新增赛道、定义规则）；

2. 数据源配置：配置各数据源的抓取范围、抓取频率（可使用默认配置，也可自定义）；

3. 数据抓取：系统自动启动多数据源抓取，生成并更新数据池，AI同步完成赛道划分、项目阶段判定；

4. 数据校准：用户查看数据池，手动修改异常项目信息、调整项目赛道（如需）；

5. 推送配置：配置邮件推送参数（邮箱、推送阶段、频率）；

6. 接收推送：系统按配置推送分阶段项目清单，用户点击链接查看项目详情，进行后续sourcing操作；

7. 持续优化：用户根据使用需求，调整赛道规则、推送配置、抓取规则，AI根据人工调整记录优化分析准确率。

# 六、风险与应对方案

|潜在风险|应对方案|
|---|---|
|数据源反爬限制，导致抓取失败|采用模拟人工操作、IP轮换、控制抓取频率等反爬应对策略；针对各平台特性优化抓取方案（如Product Hunt使用官方API）；抓取失败后自动重试，标记异常数据源并提醒用户；参考成熟数据抓取服务的反爬经验，持续优化抓取策略。|
|AI赛道划分准确率不足，不符合用户预期|提供人工调整入口，用户修改赛道后，AI学习调整逻辑，优化算法；支持用户细化赛道关键词、完善赛道定义；定期统计准确率，手动优化AI分析规则，结合用户反馈迭代模型。|
|数据更新不及时，影响项目推送时效性|优化抓取频率，重点数据源（微信公众号、小红书群）缩短更新间隔；建立抓取监控机制，抓取异常时立即提醒技术人员处理；优化数据清洗、分析流程，缩短全流程耗时。|
|用户自定义赛道过多，导致AI判定混乱|限制赛道数量（建议不超过20个）；提供赛道分类模板，引导用户规范划分；AI判定时，优先匹配最贴合的赛道，标记模糊匹配的项目，提醒用户手动确认。|
|数据泄露（如项目信息、用户配置）|采用加密存储技术，保护用户数据和抓取数据；设置用户权限管理，仅用户本人可查看自己的配置和数据；定期进行安全检测，防范数据泄露风险，符合数据安全相关规范。|
